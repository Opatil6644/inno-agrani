# Setup Overview: Text-to-Image Automation Pipeline (EvalGIM)
## 1. Project Overview
The Text-to-Image Automation Pipeline is a specialized framework built on top of the EvalGIM library. It is designed to automate three critical aspects of Generative AI development:
- Evaluation: Measuring the quality, fidelity, and diversity of images generated by models using the COCO validation dataset.
- Performance: Latency and throughput tests.
- Profiling: Analyzing the underlying hardware performance, kernel execution, and computational efficiency (latency/throughput) using NVIDIA Nsight Systems.

## 2. System Architecture & Workflow
The pipeline follows a modular execution flow, controlled primarily through Bash scripts and JSON configurations.

### 2.1 Configuration Layer
user_evaluation_settings.json: The central "brain" of the setup. It controls HuggingFace authentication, dataset paths, and generation parameters (batch size, sample count).
master_model_list.txt: A registry of models. Users can toggle specific models for evaluation by commenting/uncommenting lines in this file.

### 2.2 Execution Pipeline
- Setup Phase: Handles dependency installation and directory permissioning.
- Generation Phase: Pulls models from HuggingFace and generates images based on COCO prompts.
- Profiling Phase: Hooks into Nsight Systems to capture GPU kernel summaries and cuBLAS function calls.
- Metric Calculation Phase: Computes Marginal and Conditional metrics.

## 3. Metric Definitions
The setup evaluates models based on two distinct categories of metrics:
- Marginal Metrics (Quality & Distribution)
- FID (Fréchet Inception Distance): Measures the similarity between the distribution of generated images and real images.
- Precision/Recall: Precision measures how much of the generated data falls within the real data distribution; Recall measures how much of the real data distribution is covered by the model.
- Diversity & Coverage: Evaluates how varied the model outputs are and how well they span the target dataset.
- Conditional Metrics (Alignment)
- CLIPScore: Measures how well the generated image matches the input text prompt (Visual-Text alignment).

## 4. Performance Profiling Outputs
- Unlike standard evaluation scripts, this setup provides deep-dive hardware profiling. All results are stored in the Profile_Details/ subdirectory for each model:
- Kernel Summaries: CSV files detail which GPU kernels (Open vs. Closed source) were utilized most frequently.
- MNK Details: Provides matrix multiplication dimensions (M, N, K) which are critical for optimizing tensor core utilization.
- Throughput/Latency: Calculated files (latency.json, throughput.json) provide a clear picture of real-world inference speed.

## 5. Directory Structure & Result Aggregation
The pipeline is designed for high-scale comparison. While individual model details are stored in subfolders, the root Results/ directory generates Aggregated Files:
- results.csv: A master sheet of all model scores.
  
- latency_throughput_summary.csv: A comparative look at performance across all tested models.
  
- cublas_func_calls.csv
Contains logs of all cuBLAS API function calls made during execution.

High-level summary of all GPU kernels executed.

- mnk_details.csv

## 6. Dependencies & Troubleshooting
- Tooling: Ensure jq is installed; the scripts use it to parse JSON configurations dynamically.
- Environment: Always run scripts/setup/setup.sh after cloning to ensure the environment pathing is correctly set for your specific Linux distribution.
- Hardware: A high-VRAM NVIDIA GPU is required, as Nsight Systems and image generation (especially at 5000+ samples) are resource-intensive.
